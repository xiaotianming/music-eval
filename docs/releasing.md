# 发布流程

当前版本：0.1.0，待发布。

## 首次发布准备

1. 确定托管仓库、维护者和私密安全报告渠道，补充 `CITATION.cff` 中的仓库链接与作者信息。
2. 核对项目 MIT 授权和 [第三方许可](../THIRD_PARTY_NOTICES.md)。SongEval 的许可冲突需要向上游确认，当前按非商业研究用途集成。
3. 检查 `git ls-files`，确保仓库只收录项目代码、文档和可公开的测试记录。运行数据、环境、音频、权重和凭据由 `.gitignore` 排除或在提交前移出。
4. 分发第三方源码、模型或媒体时，保留对应许可和来源。

## 发布新版本

1. 同步 Python、前端和引用元数据中的版本号，更新 CHANGELOG。评估数值或格式变化需说明协议及兼容性影响。
2. 在干净检出环境中运行 `uv sync --locked --extra dev`、Python 测试、`npm ci` 和生产构建。涉及模型的变更另跑对应推理测试，并记录环境、参数和结果。
3. 检查 [依赖安全状态](security-status.md)，处理影响发布的通告。
4. 检查公开文档、示例和日志中的路径及敏感数据；每次实测保留日期和所用版本。
5. 推送到目标仓库，确认 CI 通过后创建版本标签并编写发布说明。

## 平台支持

完整应用及模型栈已在 Windows 实测；CI 覆盖 Windows/Linux 核心测试和前端构建。其他平台的模型安装支持需补充安装脚本和推理验证。
