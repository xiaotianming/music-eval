## 浏览器验收

通过本地浏览器实际操作：载入四首明确标记的合成和弦 → 选择音频 → 配置基础检查和 CLAP → 任务完成 → 同提示词作品对比 → 匿名 A/B → 跳过偏好判断并保存流程测试备注 → 揭晓模型。

网页中示例任务真实完成 8/8 项；静音示例的静音比例为 8.33%，对应 12 秒文件中的 1 秒静音。另一个示例没有该静音段。网页显示的 CLAP 分数由真实权重计算，不是前端演示常量。

本次浏览器可视视口较窄，已检查并修复窄屏标题、筛选区与对比卡片布局。桌面布局由同一响应式 CSS 提供，尚未在所有浏览器和屏幕尺寸上做独立视觉验收。音频端点和媒体控件已检查，但没有把程序化测试描述为人类主观听感评价。

## 真实模型验证（非模拟）

- [model-smoke.json](model-smoke.json)：固定模型离线运行。中文“悲伤的钢琴独奏，缓慢、柔和，没有鼓。”翻译为 “Sad piano solo, slow, soft, no drums.”；SongEval 对上游 144.4 秒 MP3 返回五维有限分数；纯音乐默认明确跳过。
- [fad-smoke.json](fad-smoke.json)：使用原 LAION 音乐 checkpoint 的真实推理；四个两秒合成音频组成测试集合。首次聚合后删除这些测试音频的嵌入缓存，再以离线模式重新加载模型并提取嵌入，得到相同距离。这里验证可运行性，不验证真实音乐质量相关性。
- [chinese-clap-smoke.json](chinese-clap-smoke.json)：中文提示词自动本地翻译后，离线完成整曲 CLAP；保存实际英文评分文本和窗口分数。

初次实测发现并修复：Windows 符号链接权限、翻译依赖缺少 protobuf/SentencePiece 文件、FAD 上游未固定的 RoBERTa 初始化下载、SongEval 与官方重采样方式差异。固定修订的 `.bin` 模型显式加载，避免 Transformers 自动访问额外的 safetensors 转换分支。

## 本机性能

详细测量保存在 [benchmark-basic.json](benchmark-basic.json)、[benchmark-clap.json](benchmark-clap.json)、[benchmark-songeval.json](benchmark-songeval.json)。输入为 30/180/300 秒合成和弦，仅用于资源与性能测试。

CLAP 第一轮明确删除该合成输入的可再生成音频嵌入，第二轮复用嵌入；两轮均新建进程及加载模型。因此第二轮不是常驻模型热推理，也不是整项结果缓存命中的速度。其他模型两轮均重新推理。模型下载时间不计入这些数字。

测试期间有其他安装、浏览器及评估负载并行，且可能有 Windows 文件扫描、操作系统缓存和温度影响。记录用于确认本机 CPU 可运行，不作为生产吞吐承诺，也不证明不同音乐内容的耗时相同。实际批量评估程序只运行一个推理子进程。

## 尚需使用真实业务数据验证

- 用户尚未提供实际候选模型、生成样本或真实参考音乐库；没有产出业务模型排名或音质合格结论。
- FAD 仅完成合成集合推理验证；真实参考库的风格、人声、语言、时长匹配以及样本量充分性需在接入数据后判断。
- 当前没有收集人类听感偏好。浏览器验收选择“跳过”，不会制造偏好胜率。
- 没有跨 CPU、Linux/macOS、浏览器全矩阵或长时间大规模压力测试。

所有未计算、失败和不适用项都保留明确状态，不用零分或虚构分数填充。
