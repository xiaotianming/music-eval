# 发布准备

当前为 0.1.0 开发版本。初始化 Git 不代表已经公开发布；在获得实际远程仓库地址之前，不填写虚构的项目链接。

## 首次公开仓库

- 确认 `LICENSE` 的项目原创代码 MIT 授权符合维护者意图；第三方组件仍遵循 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。SongEval 上游许可声明存在冲突，未澄清前保留研究用途限制。
- 配置真实仓库地址、维护者和安全报告渠道，再补充 `CITATION.cff` 中的 repository-code / URL / 经核实的作者信息。
- 不提交 `.venv*`、`node_modules`、`data/`、`vendor/`、音频、模型权重、凭据及私有日志。`git ls-files` 不应出现这些文件。
- 如需对外分发第三方源码、模型或媒体，单独核对对应授权。当前方案只提交适配代码、锁文件及下载脚本。

## 每次版本发布

1. 更新 Python 和前端的版本、CHANGELOG 及引用元数据。变更评估数值时记录协议影响；破坏性改动不能仅隐藏在依赖更新中。
2. 在干净检出环境运行 `uv sync --locked --extra dev`、Python 测试、`npm ci` 与生产构建。CI 配置默认不下载大模型；真实模型验证仍需单独执行并记录。
3. 审查依赖通告及未解决事项。不要把冻结的研究模型栈宣传为可安全公网部署的服务。
4. 检查代码、文档和示例中无个人路径、访问令牌、私人音乐与虚构的评估结论；不要覆盖历史验收记录来冒充新版本已验证。
5. 在真实远程 CI 通过、许可及来源核对完成后，由维护者创建版本标签并发布说明。公开发布与推送需要明确的目标仓库。

## 支持范围

目前完整应用和模型栈在 Windows 上实测。CI 配置覆盖 Windows/Linux 的基础测试和前端构建，但在真实远程运行前不宣称该 CI 已通过，也不把 Linux 核心测试等同于完整可选模型安装支持。
